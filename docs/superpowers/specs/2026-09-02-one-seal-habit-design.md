# 一日一印學習機制設計規格

日期：2026-09-02  
狀態：待使用者書面確認後進入實作  
適用專案：六書造字堂 iOS App

## 一、設計目標

「一日一印」要讓學生放學後願意自主打開 App，每天用 5–15 分鐘完成一次有效的六書回憶練習，感受到進展，也能在完成後安心離開。

核心原則：

1. 每一天願意回來。
2. 每一次真的記得更多。
3. 完成後可以安心離開。

本階段採用「有限場次的敘事修行」設計，不採無限任務、連續登入懲罰、隨機獎勵箱或以焦慮驅動的排行榜。遊戲化服務學習，不以延長使用時間為目的。

## 二、本階段範圍

本階段一次整合以下五個部分：

- 今日一印：每天一條清楚、短而完整的學習路徑。
- 一字開卷：60–90 秒即可完成的最低行動。
- 七日入堂：完成七次修行後建立基本學習節奏。
- 三印成週：每週完成三個不同日期的修行即可達標。
- 墨乾時刻：15 分鐘提醒、20 分鐘停止派發新題。

暫不納入：推播通知、班級連線、全服排行榜、教師後台、付費機制、完整字例證據庫重寫、50 條評審中的其他獨立改善項目，以及 App Store 發布流程。

## 三、學習判定

### 3.1 有效作答

一次有效作答必須先看到題目並做出分類選擇，之後才能揭示答案。單純閱讀解析、重複點擊已作答題目或返回同一題，不得重複計次。

- 答對：記為「已嘗試」及「答對」，依既有規則更新掌握度。
- 答錯：記為「已嘗試」，可以完成今日任務，但不增加正確數或掌握度。
- 放棄或未選答案：不算完成該題。

這樣能把「維持習慣」和「真正掌握」分開：學生不會因答錯而失去當天印記，也不能靠閱讀答案假裝學會。

目前揭曉答案後的通用判據可以保留為解說，但不得當作學生已完成字例理由判斷的證據。完整的逐字證據題庫另列後續項目。

### 3.2 今日一印完成條件

一般日需完成當日規劃的 5 個不同字例，且每個字例都至少有一次有效作答。正確率獨立呈現，不影響是否取得當日印記。

同一字例在同一天只能計入一次；重開 App、切換模式或重複進入同題都不能增加進度。

### 3.3 日期規則

所有日與週的切換以 `Asia/Taipei` 為準。今日修行開始時建立不可變的 `dateKey`；跨午夜時，已開始的場次仍歸入開始日期，完成或離開後才建立新一天的內容。使用時間計時器則在台北日期切換時歸零。

## 四、每日內容規劃

`DailySealPlanner` 是純 Swift、可重現且可單元測試的規劃器。相同日期、相同內容與相同進度必須產生相同順序，不能因重開 App 換題。

一般日的 5 題優先順序如下：

1. 昨日伏筆：昨日答錯或最不穩定的一字。
2. 到期複習：依間隔複習狀態選取。
3. 弱項回鍋：優先補學生較弱的六書類別。
4. 今日新字：尚未熟悉的字例。
5. 平衡題：補足類別分布，避免五題集中於同一類。

規劃器必須：

- 排除爭議字例與資料狀態不完整的字例。
- 保證題目 ID 不重複。
- 題庫不足時依「到期、弱項、未熟、新近正確最少」依序補位。
- 不足五個合法字例時顯示資料異常狀態，不得用重複題灌滿。

## 五、一字開卷與主流程

首頁最上方放置單一主要入口：

- 尚未開始：`今日一印`
- 已開始未完成：`繼續修行`
- 今日已完成：`今日已落印`，下方提供不帶額外獎勵的 `自由探索`

進入後先做「一字開卷」：完成今日第一個字例即達成最低行動，畫面給予溫和回饋，並讓學生選擇繼續完成餘下四題或先離開。只有完成全部當日規劃才取得今日印記。

標準流程：

1. 首頁顯示今日主題、預估 5–15 分鐘與目前進度。
2. 一字開卷完成第一題。
3. 依序完成餘下四題，每題揭曉後顯示簡短判據。
4. 第五題完成後進入落印結算。
5. 結算顯示完成、答對數、需要再磨的字與下一次提示。
6. 返回首頁後不再主動派發新任務。

## 六、七日入堂

七日入堂以「完成七次今日修行」推進，不要求日曆連續，也不因中斷歸零。

| 階段 | 名稱 | 完成事件 |
|---|---|---|
| 第 1 印 | 定錨 | 選擇放學後、晚餐後、洗澡前或自訂學習錨點，完成至少一題 |
| 第 2 印 | 回聲 | 先回答昨日伏筆，再接觸兩個新字 |
| 第 3 印 | 擇路 | 選擇想優先修行的六書類別 |
| 第 4 印 | 回鍋 | 再遇一次先前答錯或低掌握字例 |
| 第 5 印 | 小成 | 完成一組五題微型挑戰 |
| 第 6 印 | 立證 | 作答前先在心中說出一句判據，再選分類；本階段不錄音、不蒐集文字 |
| 第 7 印 | 入堂 | 查看七次修行回顧，設定下週的類別目標 |

第 1 印的完成事件是七日入堂的新手引導特例，可以在完成一字開卷後取得；第 2–7 印需完成該日規劃。每個階段只能完成一次，歷史永久保留。

## 七、三印成週

每個台北時區的曆週（週一至週日）以三個不同日期的完成印記達標：

- 第一印「開卷」：本週第一次完成。
- 第二印「磨字」：本週第二次完成。
- 第三印「試鋒」：本週第三次完成。

超過三天仍可自由修行，但不提高獎勵、不製造無限連鎖任務。漏掉某一天不扣分、不清空紀錄；下週自然開始新的三印成週。復歸印屬有效重新開始，因此可以計入每週完成日，但同一天永遠最多算一印。

## 八、缺席復歸

依最後一個完成日期計算缺席天數：

| 缺席天數 | 復歸內容 | 完成認定 |
|---|---|---|
| 0–2 天 | 一般 5 題 | 一般印 |
| 3–6 天 | 一字重新落筆，優先選熟悉且非爭議字例 | 復歸一字印，可計入本週 |
| 7 天以上 | 三字暖身：熟悉字、弱項字、自選類別各一 | 復歸三字印，可計入本週 |

復歸印不提高掌握度判定標準，也不提供額外倍率。完成後下一個日期恢復一般 5 題。任何缺席都不移除既有印記、階段或收藏。

## 九、墨乾時刻

計時以同一台北日期內 App 在前景的有效使用秒數累積，涵蓋首頁、學習、字庫與其他模式；切換分頁、背景再回來或重開 App 都不能重置。

- 15 分鐘：顯示一次「墨將乾」提醒，告知剩餘約 5 分鐘。
- 20 分鐘：不再開啟新題；正在作答的題目可完成，之後進入收尾畫面。
- 收尾畫面：顯示今日完成內容，提供離開 App 的明確建議。
- 今日已達 20 分鐘後仍可查看進度與字例說明，但不能再取得印記、掌握度或其他獎勵。
- 設定頁提供一次明確的「今日繼續自由閱讀」選項，只開放無獎勵的內容瀏覽，不解除作答鎖定。

此機制沒有倒數壓迫動畫，不以快答換取額外獎勵。

## 十、介面設計

新增或調整的主要元件：

- `DailySealCard`：首頁第一張卡，唯一主要行動按鈕。
- `DailySealSessionView`：承載當日 1／5 至 5／5 的短場次。
- `SealTaskView`：重用既有題目殼層，先選後揭曉。
- `SealCompletionView`：落印、正確數、待複習字與收尾。
- `SevenDayEntryView`：只在對應階段顯示一個簡短引導。
- `WeeklySealStrip`：三格週印，不使用會歸零的火焰連勝視覺。
- `InkDryView`：15 分鐘提示與 20 分鐘收尾。

首頁資訊優先順序：今日一印卡、七日／週進度、原有統計與探索入口。iPhone 使用單欄；iPad 可雙欄，但主要按鈕與語意順序一致。所有狀態不可只靠顏色傳達，需支援 Dynamic Type、VoiceOver 與減少動態效果。

## 十一、資料模型與相容性

`LearningProgress` 的原生 schema 由 2 升為 3，所有新增欄位皆可選或提供預設值，確保第二階段舊存檔仍可解碼。

建議模型：

```swift
struct HabitProgress: Codable, Equatable {
    var anchor: StudyAnchor?
    var preferredCategory: LiushuCategory?
    var dailyRecords: [String: DailySealRecord]
    var sevenDay: SevenDayProgress
    var usageClock: UsageClockState
}

struct DailySealRecord: Codable, Equatable {
    var dateKey: String
    var plannedCharacterIDs: [String]
    var attemptedCharacterIDs: [String]
    var correctCharacterIDs: [String]
    var kind: SealKind
    var startedAt: Date
    var completedAt: Date?
    var closedAt: Date?
}

struct SevenDayProgress: Codable, Equatable {
    var completedStages: [Int]
    var completedAt: [Int: Date]
}

struct UsageClockState: Codable, Equatable {
    var dateKey: String
    var foregroundSeconds: TimeInterval
    var didShowWarning: Bool
    var didReachStop: Bool
}
```

`StudyAnchor` 支援放學後、晚餐後、洗澡前與自訂文字；資料只存本機，不在本階段建立通知。`SealKind` 包含 `normal`、`recoveryOne`、`recoveryThree`。

網頁版進度匯出格式新增可選的 `nativeHabit` 區段，以保留 iOS 習慣資料；舊匯出檔沒有此區段時使用空白預設值。iOS 匯出再匯入必須完整往返；舊網頁若讀取後重新輸出，可能不保留原生擴充欄位，介面需在使用者匯出前提示此限制。

## 十二、資料流與生命週期

1. `AppModel` 持有 `LearningProgress`、今日規劃與目前場次。
2. 首頁向 `DailySealPlanner` 請求今日或復歸方案。
3. 規劃一旦存入 `DailySealRecord`，同日不再重新抽選。
4. 每題首次提交分類時，原子式記錄嘗試與正確結果。
5. 達到當日題數後記錄完成時間，再更新七日與週進度。
6. `RootView` 監聽 scene phase；進入前景開始計時，離開前景立即落盤。
7. 日期切換時建立新的 `UsageClockState`；進行中的昨日場次保持原 `dateKey`。

App 非預期關閉後重新開啟，必須回到尚未完成的下一題。壞掉或缺少新增欄位的舊資料採空白習慣進度，不影響既有答題、收藏與統計資料。若合法題庫不足，顯示可理解的錯誤與返回入口，不能崩潰或重複出題。

## 十三、倫理與隱私界線

- 不建立連勝中斷懲罰。
- 不使用隨機寶箱、稀有掉落或「再一題才可領取」誘導。
- 不顯示全服排名或公開學生弱項。
- 不蒐集姓名、聲音、自由文字或其他個人資料。
- 不在本階段申請通知權限。
- 所有成就與進度均可離線使用。

## 十四、驗收條件

### 單元與資料測試

1. 第二階段 schema 2 JSON 可解碼，新增欄位得到安全預設值。
2. 相同日期與狀態產生相同的今日題目，且 ID 全部唯一。
3. 答錯會完成該題，但不增加正確數與掌握度。
4. 同一題重複提交不能重複計數。
5. 一般日完成 5 個不同有效作答後取得印記。
6. 七日入堂依完成事件前進，不要求連續日期，也不會倒退。
7. 三印成週只計算同一曆週中三個不同完成日期。
8. 缺席 3–6 天產生一字復歸；7 天以上產生三字復歸；完成後下一日恢復一般方案。
9. 15 分鐘只提醒一次；20 分鐘後禁止開始新題。
10. 切換分頁、背景／前景與同日重開 App 不會重置累積時間。
11. 20 分鐘當下的題目可以完成，完成後必須收尾。
12. `nativeHabit` 經 iOS 匯出與匯入後資料一致。

### 介面與人工驗收

1. 首頁第一眼只有一個明確的今日主要行動。
2. 能在 60–90 秒內完成一字開卷並安全離開。
3. 一般 5 題、兩種復歸與落印畫面都可完整走完。
4. 墨乾提醒與停止狀態可實際觸發，不遮住正在作答的必要資訊。
5. iPhone 與 iPad 版面可用；最大 Dynamic Type 不截斷主要操作。
6. VoiceOver 能讀出題數、答案狀態、週印與七日階段，不只朗讀裝飾名稱。
7. 開啟減少動態效果後，所有狀態變更仍清楚可辨。

## 十五、實作切片建議

1. 資料模型、相容解碼、日期工具與規劃器。
2. 今日一印場次與有效作答記錄。
3. 首頁卡、落印頁、七日入堂與三印成週。
4. 復歸方案。
5. 墨乾時刻與 scene phase 持久化。
6. 匯出／匯入擴充、無障礙與完整測試。

每個切片都應維持可建置、可重開且可測試，避免到最後才串接資料持久化。
